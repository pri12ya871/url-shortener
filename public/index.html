          Under the hood

          What happens in the 8 ms.

          The redirect path touches Redis first, Postgres only on a miss, and writes nothing before responding.

          1. 01

            Shape check

            A malformed code is rejected before Redis or Postgres is touched at all — scanners cost nothing.

          2. 02

            Cache-aside read

            Hits come from Redis. Misses — including “no such code” — are cached too, so a scanner can’t hammer the database.

          3. 03

            302, immediately

            A 301 would be cached by the browser and every later click would never reach us. Analytics would quietly flatline.

          4. 04

            Write after the wire

            setImmediate defers the insert. A dropped click is acceptable; a slow redirect is not.

          ⚡ Collisions settled by the index

          INSERT … ON CONFLICT (code) DO NOTHING, retried. Never SELECT-then-INSERT, which races between the two statements.

          🛟 Redis is optional by design

          Every cache helper fails soft and the rate limiter fails open. Redis going down degrades latency, never availability.

          🔒 No raw IPs, ever

          Visitors are a salted SHA-256 truncated to 32 chars; referrers are stored origin-only. Enough to count uniques, not enough to reverse.
